# 05 识别质量评测

> 文档编号：05
> 项目：Go版人脸核验服务
> 状态：已实现
> 证据基线：`internal/eval`、`cmd/eval`、`internal/adapter/onnx/testdata/`、LFW 200 人基线、AxonData PAD 基线

## 1. 工具用途

`cmd/eval` 是独立的离线评测命令，不启动 HTTP 服务，也不依赖 PostgreSQL/Redis。它加载人脸引擎，按清单计算：

- 同人配对与异人配对的余弦分数；
- FAR、FRR、TAR、EER、ROC AUC；
- 指定目标 FAR 下的推荐阈值与 FRR；
- 活体序列的最低分、均值，以及 APCER/BPCER；
- 明细 CSV 与汇总 JSON，可用于 CI 门禁。

## 2. 运行方式

```bash
go run ./cmd/eval \
  -manifest eval/manifest.example.yaml \
  -model-dir models \
  -out eval/out \
  -target-far 0.001 \
  -liveness-threshold 0.85
```

常用参数：

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `-manifest` | 无 | 必填，YAML/JSON 清单 |
| `-model-dir` | `models` | 三个 ONNX 模型目录 |
| `-out` | `eval/out` | 报告输出目录 |
| `-target-far` | `0.001` | 目标误识率 |
| `-liveness-threshold` | `0.85` | 服务活体阈值 |
| `-max-impostor-pairs` | `0` | 异人配对上限，0 表示全部 |
| `-threshold-step` | `0` | 阈值步长，0 表示使用清单配置 |
| `-max-frr-at-target` | `-1` | FRR 门禁，负数表示不启用 |
| `-max-apcer` | `-1` | APCER 门禁，负数表示不启用 |
| `-max-bpcer` | `-1` | BPCER 门禁，负数表示不启用 |
| `-detection-threshold` | `0.9` | 检测阈值，应与服务保持一致 |
| `-nms-threshold` | `0.3` | NMS IoU 阈值 |
| `-analysis-threshold` | `0.6` | 特征与活体路径的检测阈值 |
| `-liveness-crop-scale` | `2.7` | 活体裁剪倍率 |

## 3. 清单格式

```yaml
identities:
  - id: person_001
    images: [path/1.jpg, path/2.jpg]
    meta: { age_band: "20-30", device: "iphone" }
  - id: person_002
    images: [path/3.jpg, path/4.jpg]

liveness:
  bona_fide:
    - id: live_001
      images: [path/live_1.jpg, path/live_2.jpg]
  attacks:
    - id: print_001
      label: print
      images: [path/print_1.jpg]

options:
  max_impostor_pairs: 200000
  threshold_step: 0.01
```

规则：

- 至少两个可检测的 identity，且至少一个 identity 含两张可检测图片，才能计算 FAR/FRR。
- 同人配对按 identity 内两两组合；异人配对按 identity 之间两两组合。
- 活体序列的最低分用于判定：`最低分 >= 阈值` 视为 live。
- 相对路径按清单所在目录解析；绝对路径直接使用。
- 图片只在本机读取，不上传。

## 4. 输出

| 文件 | 内容 |
| --- | --- |
| `report.json` | 汇总指标、阈值、EER、AUC、活体指标、错误列表 |
| `scores.csv` | 每对图片的类型、身份、路径与分数 |
| `roc.csv` | 各阈值下的 FAR/FRR/TAR |
| `liveness.csv` | 每个活体序列的最低分、均值与错误 |
| `liveness_metrics.csv` | 各阈值下的 APCER/BPCER |

退出码：

- `0`：评测完成且未触发门禁；
- `1`：评测失败或指标未达标；
- `2`：清单或参数错误。

## 5. 自动化与 CI

```bash
go test ./internal/eval
go run ./cmd/eval -manifest <ci 清单>.yaml -out eval/out \
  -target-far 0.001 -max-frr-at-target 0.05 \
  -max-apcer 0.01 -max-bpcer 0.05
```

建议：

- 每次提交跑小样本回归集，防止预处理或模型漂移；
- 夜间跑全量评测集，报告作为 CI artifact；
- 目标 FAR、FRR、APCER、BPCER 写入门禁参数，不达标阻止合并；
- 评测集与产出报告不得包含真实人脸原图。

## 7. 当前能力最佳档位

### 7.1 本机基线

LFW 1:1（200 个身份、605 张图，767 对同人、181,943 对异人）：

| 指标 | 中文含义 | 值 |
| --- | --- | --- |
| EER | 等错误率：FAR 与 FRR 相等时的错误率 | 2.996% |
| AUC | ROC 曲线下面积：0.5 为随机，1.0 为完美 | 0.988190 |
| FAR / FRR | 误识率 / 拒识率：不同人误放行 / 同一个人被拒绝 | 0.1396% / 4.1721% |
| 目标 FAR 0.1% | 目标误识率下的阈值与对应拒识率 | 阈值 0.36，FRR 4.4329% |

AxonData PAD（29 段真人、120 段攻击视频，8 类攻击）：

| 阈值 | APCER（攻击放行率） | BPCER（真人拒绝率） |
| --- | --- | --- |
| 0.85 | 24.17% | 17.24% |
| 0.90 | 18.33% | 17.24% |
| 0.91 | 16.67% | 17.24% |
| 0.92 | 15.83% | 17.24% |
| 0.95 | 10.83% | 24.14% |

0.91 附近达到 APCER 与 BPCER 的最佳平衡。

0.91 阈值下按攻击类型：

| 攻击类型 | 序列数 | APCER |
| --- | --- | --- |
| 3d_paper_mask | 36 | 2.78% |
| cutout | 15 | 0% |
| replay_display | 5 | 0% |
| replay_mobile | 10 | 0% |
| wrapped_3d | 10 | 10.0% |
| textile_3d | 23 | 34.8% |
| latex | 10 | 40.0% |
| silicone | 11 | 54.5% |

高仿真面具仍是主要缺口，打印与翻拍已经接近零通过。

模型对比（同一 AxonData、阈值 0.91）：

| 模型/融合 | APCER | BPCER |
| --- | --- | --- |
| MiniFASNetV2 2.7（当前） | 16.67% | 17.24% |
| V2 + V1SE 概率平均 | 17.50% | 20.69% |
| MiniFASNetV1SE 4.0 单独 | 20.83% | 3.45% |

结论：MiniFAS 系列变体和简单融合没有改善高仿真面具；继续堆同一训练分布的模型价值很低。

另测了 CelebA-Spoof 训练的 MobileNetV3 PAD（MN3）：Python 独立 YuNet 管线在 0.20 阈值下 APCER 3.3%、BPCER 10.3%，但换到 Go 服务的 YuNet 裁剪链路后为 APCER 24.2%、BPCER 24.1%，未优于 V2。按 MN3 原生裁剪（外扩 1.1/1.05、128×128、RGB、固定 mean/std）在 Go 中复跑仍为 24.2%/24.1%；根因是检测与投票语义差异，不是模型本身：同一序列 `Latex_mask_6_1_f1` 在 OpenCV 检测器中无脸、Python 记 0 分，Go 检测到大框并记 0.998。Go 已改为无脸帧计为攻击帧，但 MN3 仍未接入默认路径。

补充说明：早期还有一组 MN3 跑分（阈值 0.27，APCER 8.33%、BPCER 6.90%，两项均为个位数），该结果对模型输出又做了一次 softmax。核对后模型输出本身就是概率（`[1,2]`，索引 0 为 live），双重 softmax 改变了分数排序，因此该组数据无效，未纳入基线。有效结果只有原始概率管线的 3.3%/10.3% 与服务链路 24.2%/24.1%。

### 7.2 推荐配置

高风险场景推荐：

```bash
FACE_LIVENESS_THRESHOLD=0.91
FACE_ACTIONS_COUNT=3
FACE_FRAMES_PER_ACTION=5
FACE_ACTION_VERIFY_ENABLED=true
# 活体失败锁定
LIVENESS_GUARD_ENABLED=true
LIVENESS_GUARD_FAILURE_LIMIT=5
LIVENESS_GUARD_WINDOW_SECONDS=600
LIVENESS_GUARD_LOCK_SECONDS=300
# 高风险可选
FACE_MATCH_THRESHOLD=0.36
```

说明：

- 0.91 相比默认 0.85，在不增加真人拒绝率的情况下降低攻击放行率。
- 动作校验仍是必要门槛，用于拦截静态照片和简单重放。
- 活体失败锁定用于限制连续试探，不改变单次判定精度；锁定期间请求在消费 challenge 前被拒绝。
- 样本只有 29 段真人、120 段攻击；该档位不构成商业 PAD 合规结论。
- 高仿真面具仍有约 16.7% 的通过率，需要更强的 PAD 模型、设备风控和人工复核补充。

### 7.3 送测接口与版本冻结

仅测试环境可用，需同时满足：

```bash
APP_ENV=staging        # 不能是 production
LAB_MODE=true
```

注册 `POST /v1/liveness-checks`，返回可审计的活体证据：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `result` | string | `passed` 或 `failed` |
| `status` | string | `real`、`spoof`、`fuzzy` |
| `pad_score` | number | 序列最低 live 分 |
| `pad_threshold` | number | 本次使用的活体阈值 |
| `pad_decision` | string | 与 `status` 一致 |
| `min_frame_score` | number | 最低单帧分 |
| `mean_frame_score` | number | 平均单帧分 |
| `frame_scores` | number[] | 逐帧 live 分 |
| `live_frames` | number | 判定为 live 的帧数 |
| `attack_frames` | number | 判定为攻击的帧数 |
| `live_ratio` | number | live 帧占比 |
| `action_checked` | boolean | 是否校验了动作序列 |
| `action_passed` | boolean | 动作是否全部通过 |
| `action_code` | string | 动作失败时的错误码 |
| `action_detail` | string | 动作几何范围或失败原因 |
| `model_version` | string | 引擎模型版本 |
| `config_version` | string | 配置指纹 |
| `device_id` | string | 本次挑战绑定的设备 |
| `request_id` | string | 请求标识 |

`POST /v1/liveness-checks` 支持可选表单字段 `verify_actions=true`：启用后必须同时满足活体 real 和 challenge 动作序列全部通过，才返回 `passed`。

`GET /version` 返回冻结信息：

| 字段 | 说明 |
| --- | --- |
| `version` / `commit` | 构建版本与提交 |
| `engine` | 模型版本 |
| `model_sha256` | 三个模型文件的组合哈希 |
| `config_sha256` | 不含密钥的配置指纹 |
| `liveness_threshold` / `live_ratio_threshold` | 活体阈值 |
| `actions_count` / `frames_per_action` | 动作参数 |
| `action_verify_enabled` | 动作校验开关 |
| `lab_mode` | 是否为 lab 模式 |

启动日志同步记录上述版本、模型哈希、配置哈希与阈值；送测时冻结容器 digest、模型哈希和配置哈希，测试期间不得变更。

### 7.4 面具感知路线决策

结论：现有服务不引入新的 PAD 模型、训练数据或硬件，按当前能力上限交付，并把高仿真面具的残余风险交给业务侧风控与人工复核。

依据：

- MiniFASNetV2、V1SE、两者概率平均，以及 MN3 在本服务裁剪链路上的 APCER/BPCER 均未优于 V2；继续在同分布模型上堆叠没有收益。
- 高仿真面具需要面具感知模型或深度/IR 硬件；这两条路线都超出当前纯 RGB 静默活体的能力边界，且需要授权训练数据与专用采集设备。
- 公开数据集（AxonData 为 CC BY-NC 4.0）只能用于研发回归，不能作为训练或商业合规依据。

重启条件（满足任一）：

- 业务要求对高仿真面具自动拦截，而不是人工复核兜底；
- 获得可商用的面罩/攻击训练数据，或完成自有样本采集；
- 端侧具备深度/IR 采集能力；
- 需要对外声明符合 ISO/IEC 30107-3，或必须通过第三方实验室 PAD 测评。

## 8. 当前限制

- 已完成 LFW 200 人与 AxonData 29 段真人 / 120 段攻击的本地基线；样本仍有限，不能直接外推到业务人群。
- 指标为点估计，未计算置信区间；小样本结果不能外推。
- 未按人群、设备、光照拆分报告；清单已预留 `meta`，后续可扩展分片统计。
- 活体指标按序列最低分聚合，与服务端“任一攻击帧即 spoof”一致；未评估视频级时序模型。
- LFW 与 AxonData 均只用于研究/内部验证；AxonData 为 CC BY-NC 4.0，不能作为商业合规证据。
- 当前 PAD 基线中，高仿真面具在 0.91 阈值下仍有约 16.7% 的通过率，需要更强的 PAD 模型、设备风控与人工复核补充。
- `POST /v1/liveness-checks` 与 `/version` 仅用于测试环境；`LAB_MODE=true` 在 production 会拒绝启动。
- MiniFASNetV2/V1SE 及简单融合均未解决高仿真面具；按 7.4 决策不继续在同分布模型上堆叠，重启面具感知路线的条件见该节。
- 排查 MN3 的 NaN 时发现并修复了 onnx-gomlx 的 opset<11 `Clip` 属性未生效问题；修复后 MN3 中间值与 ONNX Runtime 对齐，NaN 消失，并在 `testdata/clip9.onnx` 增加规范回归测试。
