## 1 接口与权限

Base URL 由业务后端下发，生产与测试环境分离。所有端上接口使用业务后端签发的 5 分钟短期 JWT。

本期可用接口：

| 接口 | 方法与路径 | 鉴权 | 用途 |
| --- | --- | --- | --- |
| 挑战 | `POST /v1/challenges` | JWT | 获取 challenge、动作序列与帧数 |
| 动作预检 | `POST /v1/action-check` | JWT | 单个动作实时预检，不消费 challenge |
| 人脸录入 | `POST /v1/enrollments` | JWT | 活体与动作校验后建立或覆盖档案 |
| 档案 1:1 | `POST /v1/verifications` | JWT | 活体与动作校验后与已录入档案比对 |
| 档案查询 | `GET /v1/subjects/{subject_id}` | JWT | 查询档案状态与模型版本 |
| 档案删除 | `DELETE /v1/subjects/{subject_id}` | JWT | 合规删除档案与索引 |
| 开发令牌 | `POST /dev/token` | 无 | 仅本地开发环境签发 dev JWT |

本期不可用接口：`POST /v1/sessions`、`POST /v1/matches`、`POST /v1/liveness-checks`、`POST /v1/identifications`、`POST /v1/documents`、`GET /v1/operations/{id}`、`POST /v1/results/{jti}/consume`。调用这些路径返回 404，前端不得依赖。

请求约定：

| 项 | 说明 |
| --- | --- |
| 鉴权头 | `Authorization: Bearer <JWT>` |
| 请求标识 | `X-Request-Id`，可选，格式 `req_` 加 20 位十六进制；非法值会被忽略并重新生成，响应头回写最终 ID |
| 幂等 | 写接口可带 `Idempotency-Key`，当前版本接受但不生效 |
| JSON 接口 | `Content-Type: application/json` |
| 上传接口 | `Content-Type: multipart/form-data` |
| 单帧大小 | 不超过 2MB |
| 请求总大小 | 不超过 20MB |
| 帧数上限 | 15 |
| JWT 有效期 | 5 分钟，过期后重新向业务后端申请 |
| 开发端点 | `/dev/token`、`/dev/face-test.html` 仅本地开发，生产不可用 |

JWT 需要包含 `tenant`、`sub`、`scene`、`jti`、`ops`；`ops` 可为 JSON 数组或空格分隔字符串。当前版本不校验 `jti` 是否已使用，但 challenge 仍然一次性。

## 2 字段说明

### 2.1 通用响应

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `code` | number 或 string | 0 表示成功；失败时为错误码字符串 |
| `message` | string | 可展示的提示文案 |
| `data` | object 或 null | 业务数据 |
| `request_id` | string | 本次请求标识，排障时使用 |

响应序列化省略值为 null 的字段。subject 两个接口的 `data` 内也会带 `request_id`，其余接口只在信封层返回。

### 2.2 数据类型

| 类型 | 说明 |
| --- | --- |
| `string` | 字符串 |
| `number` | 数字；分数保留 5 位小数 |
| `boolean` | 布尔值 |
| `object` | JSON 对象 |
| `array` | 数组，元素类型按接口标注 |
| `null` | 空值；字段可能整体省略 |

### 2.3 枚举

| 枚举 | 值 | 说明 |
| --- | --- | --- |
| `mode` | `match`、`liveness`、`enroll`、`verify`、`identify`、`document` | 挑战模式；本期 open 的路由只使用 `enroll` 与 `verify` |
| `actions` | `straight`、`turn_left`、`turn_right`、`mouth_open` | 动作提示 |
| `liveness` | `real`、`spoof`、`fuzzy`、`detecting`、`error` | 活体状态；成功响应只返回 `real` |
| `subject_status` | `active`、`pending` | 档案状态 |
| `cleaned` 键 | `profile`、`images` | 删除清理项 |
| `ops` | `match`、`liveness`、`enroll`、`verify`、`identify`、`document`、`delete` | JWT 允许操作 |

### 2.4 上传通用字段

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `challenge_id` | string | 上传类接口必填 | 挑战 ID，一次性 |
| `device_id` | string | 挑战必填，上传可空 | 设备指纹摘要；上传时必须与挑战中的值一致 |
| `frames` | file[] | 上传类接口必填 | 现场帧，数量等于 `frame_count` |
| `baseline_frames` | file[] | 否 | 动作预检的正视基线帧，用于张嘴判定 |
| `action` | string | 动作预检必填 | 单个动作名 |

## 3 接口明细与示例

### 3.1 挑战接口

`POST /v1/challenges`

请求参数：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `scene` | string | 是 | 业务场景，如 `kyc` |
| `mode` | string | 是 | 本期使用 `enroll` 或 `verify` |
| `gallery` | string | 否 | 传非空值会返回 404 `GALLERY_NOT_FOUND` |
| `device_id` | string | 是 | 设备指纹摘要 |

请求示例：

```json
{
  "scene": "kyc",
  "mode": "enroll",
  "device_id": "dev_9f2c1a7b"
}
```

响应字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `challenge_id` | string | 一次性挑战 ID，格式 `ch_` 加 32 位十六进制 |
| `actions` | string[] | 动作序列，首项固定 `straight` |
| `frame_count` | number | 需要采集的帧数，等于动作数乘每段帧数，最大 15 |
| `expires_at` | string | ISO 8601，UTC 偏移格式 |
| `nonce` | string | 服务端随机串，16 位十六进制 |

响应示例：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "challenge_id": "ch_7f3a8c2d9e1b4a6f8c0d2e4a6b8c0d2e",
    "actions": ["straight", "turn_right", "mouth_open"],
    "frame_count": 15,
    "expires_at": "2026-11-14T10:05:00.0000000+00:00",
    "nonce": "5c1e9a7b2d4f6a8c"
  },
  "request_id": "req_7f3a8c2d9e1b4a6f8c0d"
}
```

### 3.2 动作预检接口

`POST /v1/action-check`

请求参数：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `action` | string | 是 | `straight`、`turn_left`、`turn_right`、`mouth_open` |
| `frames` | file[] | 是 | 当前动作的近期帧，最多 15 张 |
| `baseline_frames` | file[] | 否 | 正视段帧，张嘴判定需要 |

请求示例（multipart 字段）：

```text
action: turn_left
frames: face_0.jpg, face_1.jpg, face_2.jpg, face_3.jpg, face_4.jpg
baseline_frames: straight_0.jpg, straight_1.jpg
```

响应字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `satisfied` | boolean | 当前动作是否达标 |
| `detail` | string | 无脸时为 `NO_FACE`；有脸时为几何范围文本 |

响应示例：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "satisfied": true,
    "detail": "yaw -0.312~-0.201, mouth 0.401~0.423"
  },
  "request_id": "req_5c1e9a7b2d4f6a8c0e1f"
}
```

说明：预检不消费 challenge、不写库，可在每个动作分段采集时反复调用；最终结果仍以 enroll 或 verify 的整单校验为准。

### 3.3 人脸录入接口

`POST /v1/enrollments`

请求参数：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `challenge_id` | string | 是 | 模式为 `enroll` 的挑战 |
| `device_id` | string | 否 | 必须与挑战中的值一致 |
| `frames` | file[] | 是 | 帧数必须等于挑战的 `frame_count` |

请求示例（multipart 字段）：

```text
challenge_id: ch_7f3a8c2d9e1b4a6f8c0d2e4a6b8c0d2e
device_id: dev_9f2c1a7b
frames: face_0.jpg, face_1.jpg, ... face_14.jpg
```

响应字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `profile_id` | string | 32 位无连字符 UUID |
| `status` | string | 固定 `active` |
| `model_version` | string | 固定 `mica-sface-128d-1.0.2` |

响应示例：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "profile_id": "8f14e45fceea167a5a36dedd4bea2543",
    "status": "active",
    "model_version": "mica-sface-128d-1.0.2"
  },
  "request_id": "req_2d4f6a8c0e1f3b5d7a9c"
}
```

失败时按顺序返回活体、质量、动作、人脸错误；challenge 一旦消费，重试必须重新申请。

### 3.4 档案 1:1 接口

`POST /v1/verifications`

请求参数：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `challenge_id` | string | 是 | 模式为 `verify` 的挑战 |
| `device_id` | string | 否 | 必须与挑战中的值一致 |
| `frames` | file[] | 是 | 帧数必须等于挑战的 `frame_count` |

请求示例（multipart 字段）：

```text
challenge_id: ch_1a2b3c4d5e6f7a8b9c0d1e2f3a4b5c6d
device_id: dev_9f2c1a7b
frames: face_0.jpg, face_1.jpg, ... face_14.jpg
```

响应字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `result` | string | 固定 `passed` |
| `score` | number | 余弦相似度，5 位小数 |
| `liveness` | string | 固定 `real` |
| `verification_token` | string | 原始 JWT，不含前缀 |

响应示例：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "result": "passed",
    "score": 0.79321,
    "liveness": "real",
    "verification_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJ0ZW5hbnQiOiJkZXYifQ.signature"
  },
  "request_id": "req_9b8c7d6e5f4a3b2c1d0e"
}
```

失败分支：

| 场景 | HTTP | 错误码 |
| --- | --- | --- |
| 活体出现攻击帧 | 422 | `LIVENESS_FAILED` |
| 活体 Fuzzy | 422 | `LOW_QUALITY` |
| 主体未录入或档案不存在 | 404 | `FACE_NOT_ENROLLED` |
| 动作未完成 | 422 | `ACTION_MISMATCH` |
| 分数低于 0.35 | 422 | `FACE_MISMATCH` |
| 模型版本不一致 | 503 | `SERVICE_UNAVAILABLE` |

### 3.5 档案查询接口

`GET /v1/subjects/{subject_id}`

请求参数：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `subject_id` | string | 是 | 路径参数，业务用户 ID，对应 JWT 的 `sub` |

请求示例：

```text
GET /v1/subjects/user_10086
Authorization: Bearer <JWT>
```

响应字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `subject_id` | string | 业务用户 ID |
| `status` | string | `active` 或 `pending` |
| `model_version` | string 或 null | 无 active 档案时省略 |
| `request_id` | string | 本次请求标识 |

响应示例：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "subject_id": "user_10086",
    "status": "active",
    "model_version": "mica-sface-128d-1.0.2",
    "request_id": "req_3c2b1a0f9e8d7c6b5a4f"
  },
  "request_id": "req_3c2b1a0f9e8d7c6b5a4f"
}
```

主体不存在或已删除时返回 404 `FACE_NOT_ENROLLED`。

## 4 错误文案

| 错误码 | HTTP | 建议文案 | 前端处理 |
| --- | --- | --- | --- |
| `AUTH_INVALID` | 401 | 登录状态已失效，请重新进入 | 重新获取 JWT |
| `TENANT_DISABLED` | 403 | 当前业务未开通人脸核验 | 不重试，联系业务方 |
| `QUOTA_EXCEEDED` | 429 | 当前验证人数较多，请稍后再试 | 退避后重试 |
| `CHALLENGE_EXPIRED` | 409 | 验证已超时，请重新发起 | 重新申请 challenge |
| `CHALLENGE_REPLAY` | 409 | 本次验证已使用，请重新发起 | 重新申请 challenge |
| `NO_FACE` | 422 | 未检测到人脸，请正对镜头 | 重拍 |
| `MULTI_FACE` | 422 | 画面中只能有一个人 | 重拍 |
| `LOW_QUALITY` | 422 | 画面不清晰或格式不支持，请调整后重试 | 重拍 |
| `LIVENESS_FAILED` | 422 | 活体检测未通过，请重试 | 限次重试 |
| `ACTION_MISMATCH` | 422 | 动作未完成，请按提示重试 | 重新采集该动作 |
| `FACE_MISMATCH` | 422 | 人脸不一致，请重试 | 限次重试或人工 |
| `FACE_NOT_ENROLLED` | 404 | 尚未录入人脸，请先完成认证 | 引导 enroll |
| `GALLERY_NOT_FOUND` | 404 | 人脸库不存在或本期未开放 | 不重试 |
| `SERVICE_UNAVAILABLE` | 503 | 服务暂不可用，请稍后再试 | 退避后重试或降级 |
| `DEV_DISABLED` | 404 | 接口不存在 | 不重试 |
| `IDENTIFY_REVIEW` | 200 | 需要人工复核 | 本期不返回 |
| `DOCUMENT_UNSUPPORTED` | 422 | 暂不支持该证件类型 | 本期不返回 |
| `DOCUMENT_LOW_CONFIDENCE` | 422 | 证件识别不清晰，请重拍 | 本期不返回 |
| `DOCUMENT_INVALID` | 422 | 证件信息校验未通过 | 本期不返回 |
| `OPERATION_NOT_FOUND` | 404 | 任务不存在 | 本期不返回 |

## 5 注意事项

- `frame_count` 与 `actions` 以 challenge 响应为准，前端不得写死。
- 上传帧数必须精确等于 `frame_count`；数量不符返回 401 `AUTH_INVALID`。
- `challenge_id` 一次性；失败重试必须重新申请，不要复用旧 challenge。
- `device_id` 在 challenge 与上传时必须一致，否则返回 409 `CHALLENGE_REPLAY`。
- 动作预检只是分段引导，最终必须提交完整帧走 enroll 或 verify。
- 预检通过的帧组必须原样作为该动作段的最终帧（每段 `frames_per_action` 帧）；不要追加回正帧或重新截取。
- `verification_token` 是原始 JWT，必须交回业务后端验签与消费，前端不能自行判定业务放行。
- JWT 5 分钟有效；长流程要在过期前重新获取，不要长期缓存。
- 采集使用前置摄像头，保持单脸、正脸、光线均匀；上传前压缩到 640×480 左右、JPEG 质量 0.6–0.7。
- 图片仅支持 JPEG 与 PNG；HEIC、WebP 会解码失败并返回 `LOW_QUALITY`。
- 上传成功后删除本地临时帧；不要写入相册、缓存或日志。
- `/dev/token` 与 `/dev/face-test.html` 仅本地开发可用，生产环境必须不可用。
- 错误文案可本地化，但错误码与判定语义不得改变。
