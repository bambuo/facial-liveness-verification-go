## 5. 发现并修复的问题

| 问题 | 处置 |
| --- | --- |
| onnx-gomlx 将 SFace 的 initializer 同时当作 graph input，要求调用方传入全部权重 | 本地补丁：解析输入时排除 initializer |
| onnx-gomlx 缺 PRelu 与 Dropout | 本地补丁按 ONNX 规范实现：PRelu 使用 opset 16 的 `Less + Where + Mul` 函数体；Dropout 按推理语义输出输入、mask 全 true，并拒绝 `training_mode=true`。规范用例见 `internal/adapter/onnx/testdata/` |
| MiniFASNetV2 batch 维为动态 | 编译时固定为 1 |
| 数值配置解析失败静默回退默认值 | 改为启动期失败；新增 `APP_ENV`、留存、限流、锁定、帧数组合与生产密钥校验 |
| `FACE_MAX_FRAME_BYTES` 未生效，action-check 未限制总大小 | 单帧超限返回 422 `LOW_QUALITY`；challenge/action-check/enroll/verify 统一请求体上限，超限 503“请求体过大” |
| 租户策略非法 JSON 与越界值静默回退 | 改为返回 503“租户策略配置非法”，并校验阈值范围、限流与帧数组合 |
| 原图删除失败无日志 | 单键失败写 `slog.Warn`，不阻断删除主流程 |
| Worker 被 API 必填密钥阻塞 | 新增 `LoadWorker`，只校验数据库、Redis 与留存参数 |
| 无效配置 `DB_VECTOR_DIMENSION`、`STORAGE_SIGNED_URL_TTL_SECONDS` | 移除配置项与文档；向量维度固定 128 |
| H5 动作预检与最终分段不一致 | 预检改为使用最终提交的同一组 `frames_per_action` 帧，通过即锁定，不再追加回正帧后重截；前端对接文档补充约束 |
| 动作失败会话停在 processing | enroll/verify 的动作校验失败改为先 `Finalize(failed)` 再返回 `ACTION_MISMATCH`，与实施方案的会话语义一致 |
