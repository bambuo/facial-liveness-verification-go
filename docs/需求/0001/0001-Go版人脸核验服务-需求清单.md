## 1. 原始需求

> onnx-gomlx + GOMLX_BACKEND=go

## 2. 上下文提取

- 实现语言：Go。
- 推理路线：`onnx-gomlx` 将 ONNX 模型转换为 GoMLX 计算图，运行时使用 GoMLX 纯 Go 后端（环境变量 `GOMLX_BACKEND=go`），不引入 cgo 与 `libonnxruntime`。
- 语义基线：以 `/Users/johana/Desktop/facial-liveness-verification` 当前 .NET 10 代码为准，不以该仓库设计稿中的规划项为准。
- 交付物：可构建、可运行、可测试的 Go 工程，覆盖基线中已注册的路由、用例、存储、模型流水线与清理任务。

## 3. 需求条目

| 编号 | 需求 | 验收口径 |
| --- | --- | --- |
| R1 | 使用纯 Go ONNX 推理 | 构建产物不依赖 cgo、不加载 `libonnxruntime`；三个模型可加载并推理 |
| R2 | 对齐现有语义 | 路由、请求字段、响应字段、错误码、HTTP 状态、阈值与判定顺序与基线一致 |
| R3 | 对齐数据契约 | 复用同一 DDL、同一 Redis 键语义、同一 AES-GCM 密文格式、同一 JWT claim 集合 |
| R4 | 复用同一批模型 | 加载 `models/` 下 YuNet、SFace、MiniFASNetV2 三个 `.onnx` 文件，模型版本仍为 `mica-sface-128d-1.0.2` |
| R5 | 可验证 | 单元测试覆盖策略、加密、JWT、动作判定；集成测试覆盖 HTTP 契约与真实引擎 |
| R6 | 文档先行 | 五件套、流程图、功能文档与索引先于代码落地并通过 `check-docs.mjs` |

## 4. 基线范围（代码盘点）

基线当前已注册并可工作的 HTTP 路由：

| 方法与路径 | 功能 |
| --- | --- |
| `POST /v1/challenges` | 下发 challenge、动作序列与帧数 |
| `POST /v1/action-check` | 单动作预检，不消费 challenge、不写库 |
| `POST /v1/enrollments` | 活体 + 动作校验后建立或覆盖人脸档案 |
| `POST /v1/verifications` | 活体 + 动作校验后做档案 1:1 |
| `GET /v1/subjects/{subject_id}` | 查询档案状态与模型版本 |
| `DELETE /v1/subjects/{subject_id}` | 合规删除档案、索引、原图与可删除审计字段 |
| `POST /dev/token` | 仅 Development 且 `Auth:EnableDevToken=true` 时签发 dev JWT |
| `GET /dev/face-test.html` | 仅 Development 提供本地 H5 采集页 |
| `GET /health/live` | 存活探针 |
| `GET /health/ready` | 就绪探针，返回引擎模型版本 |

基线中未注册、本期同样不实现的接口：`POST /v1/sessions`、`POST /v1/matches`、`POST /v1/liveness-checks`、`POST /v1/identifications`、`POST /v1/documents`、`GET /v1/operations/{id}`、`POST /v1/results/{jti}/consume`。
